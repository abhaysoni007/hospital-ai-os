# Hospital AI OS — Technical Risk Register

> **Status:** Phase 3 Architecture Blueprint  
> **Scope:** Technical risks with probability, impact, mitigation, detection, and ownership

---

## Risk Matrix

| ID | Risk | Probability | Impact | Severity | Mitigation | Detection | Owner |
|:---|:---|:---:|:---:|:---:|:---|:---|:---|
| **R-01** | **AI hallucination in clinical notes** — AI generates plausible but incorrect clinical information that a busy clinician may not catch | Medium | **Critical** | **High** | Evidence verification lifecycle; mandatory human review; source citations in all AI output; evaluation dataset with hallucination rate tracking | Hallucination rate metric in AI evaluation; user rejection tracking; periodic manual review | AI Module Owner |
| **R-02** | **Critical lab value misclassification** — Deterministic rule evaluator fails to flag a true critical value, or flags a non-critical value as critical | Low | **Critical** | **High** | Extensive boundary testing; clinical review of threshold configurations; rule changes require audit trail; evaluation against known clinical reference ranges | Unit tests at every threshold boundary; integration tests with realistic lab data; audit trail for rule changes | Lab Module Owner |
| **R-03** | **Authorization bypass** — A user accesses data or performs actions outside their role scope | Low | **Critical** | **High** | RBAC middleware; role-permission matrix tests for every role × endpoint; API-layer enforcement (not just UI); break-glass auditing | Authorization matrix test suite; audit log analysis for unexpected access patterns; security tests in CI | Auth Module Owner |
| **R-04** | **Audit chain integrity loss** — Hash chain broken or audit events lost, undermining tamper evidence | Low | **High** | **Medium** | Hash chain verification on read; audit write failure blocks originating operation; database-level REVOKE on UPDATE/DELETE | Chain integrity verification job (periodic); audit write failure alerts; backup verification | Audit Module Owner |
| **R-05** | **AI provider outage** — LLM API becomes unavailable for extended period | Medium | **Medium** | **Medium** | Circuit breaker with fallback; all AI features are optional enhancements over manual workflows; provider abstraction enables switching | Health check endpoint monitors AI provider; circuit breaker state alerts; latency monitoring | AI Module Owner |
| **R-06** | **PHI exposure in logs** — Sensitive patient data accidentally logged in operational logs | Low | **Critical** | **High** | Log sanitization middleware; PHI field allowlist (only IDs, never content); developer education; code review checklist | Periodic log audit for PHI patterns; automated grep-based scanning in CI | Engineering Lead |
| **R-07** | **Prompt injection attack** — Malicious input in patient data manipulates AI behavior | Medium | **Medium** | **Medium** | Delimiter separation; input parameterization; no AI tool use; output schema validation; AI cannot modify state | Adversarial test suite; anomaly detection in AI outputs; user report mechanism | AI Module Owner |
| **R-08** | **Database performance degradation** — Slow queries as data volume grows | Medium | **Medium** | **Medium** | Index strategy defined upfront; query performance analysis in development; pagination on all list endpoints; connection pooling | Slow query logging (>100ms); p95 query time monitoring; EXPLAIN ANALYZE in development | Backend Lead |
| **R-09** | **JWT token theft** — Access token stolen and used for unauthorized access | Low | **High** | **Medium** | Short token lifetime (15 min); httpOnly cookies for refresh; RS256 asymmetric signing; session binding to IP/UA; immediate revocation on suspicion | Failed auth attempt monitoring; concurrent session detection; IP anomaly detection | Auth Module Owner |
| **R-10** | **Concurrent data modification** — Two users edit the same clinical record simultaneously | Medium | **Medium** | **Medium** | Optimistic concurrency control (version column); conflict detection on save; user notification of conflicts | ConflictError (409) responses tracked; user-facing conflict resolution UI | Clinical Module Owner |
| **R-11** | **Embedding quality degradation** — Poor quality vector embeddings lead to irrelevant chart search results | Medium | **Low** | **Low** | Evaluation dataset for chart search; retrieval precision/recall metrics; content hash for re-embedding on change | Chart search evaluation metrics; user feedback mechanism; periodic embedding quality audit | AI Module Owner |
| **R-12** | **Dependency vulnerability** — Third-party npm package introduces security vulnerability | Medium | **High** | **Medium** | Pinned versions; `npm audit` in CI; minimal dependency count (Ponytail); security advisory monitoring | CI build failure on critical vulnerability; automated Dependabot alerts | Engineering Lead |
| **R-13** | **File upload attack** — Malicious file uploaded as identity document | Low | **High** | **Medium** | File type allowlist; magic bytes validation; file size limits; server-generated paths; storage outside web root | File validation logs; upload anomaly detection | Security Admin |
| **R-14** | **Architecture complexity creep** — System grows beyond modular monolith maintainability | Low | **Medium** | **Low** | Ponytail discipline; module boundary enforcement; regular architecture review; ADR process for changes | Module coupling analysis; circular dependency detection in CI; code review | Engineering Lead |
| **R-15** | **Regulatory compliance gap** — Deployment in a jurisdiction with unexpected regulatory requirements | Medium | **High** | **Medium** | Global-first architecture (no jurisdiction hardcoding); regulatory mapping deferred to pre-deployment legal review; configurable policies | Pre-deployment compliance checklist; legal review gate before production deployment | Product Owner |
