# ADR 022: Clinical Intelligence Architecture

## Status
Accepted

## Context
Phase 4 introduces Clinical Intelligence capabilities: a Clinical Timeline, a Grounded Chart Brief, and Diagnostic Historical Trends. The goal is to provide intelligent clinical synthesis without compromising the robust security, RBAC, Break-Glass, and audit invariants established in previous phases.

The challenge is preventing the AI context projection from inadvertently exposing unauthorized patient records or hallucinating clinical information, while avoiding the creation of duplicate clinical tables or competing AI orchestrators.

## Decision

1. **Timeline Projection (Read-Only)**
   We will not create a new database table for the Clinical Timeline. Instead, we dynamically project existing `encounters`, `clinical_records`, `diagnostic_orders`, `diagnostic_results`, and `tasks` via bounded queries. Deterministic chronological sorting will occur in-memory, limited to the latest 50 events for AI context construction.

2. **Authorization-Before-Projection**
   Authorization executes before any data projection. Normal access relies on existing M5 clinical scopes. Break-Glass access relies on Phase 2 interceptors. If Patient A is authorized via Break-Glass, the intelligence modules explicitly reject cross-patient access to Patient B.

3. **Ephemeral Context & AI Output**
   Chart Briefs are read-only and ephemeral. We will not persist the raw prompt, AI response, or any extracted PHI in the database or audit logs. Only a lightweight audit trail (`SEARCH_EXECUTED` or `CHART_BRIEF_GENERATED` analogue) is appended to `audit_events`. AI outputs are never automatically bound to clinical records; they serve strictly as decision support.

4. **Grounded Provenance**
   The Chart Brief capability uses the pre-existing M12 `chart_search` capability constraint (or an equivalent strict structure). Every factual claim generated by the model must cite a `sourceId` strictly belonging to the authorized context payload. The backend will validate citations before serving them to the frontend.

5. **Diagnostic Trend Semantics**
   Historical diagnostic trends limit retrieval to the 5 most recent eligible results (excluding cancelled or invalid statuses) for a given `testCode` on the identical patient. Trends are for visualization and do not drive autonomous diagnostic algorithms.

## Consequences
- **Performance**: Capable bounding prevents unbounded context token costs and guarantees stable API latencies. Phase 3 indexes heavily optimize the timeline collection phase.
- **Safety**: Purely read-only constraints prevent the AI subsystem from corrupting clinical data. Missing data (information gaps) are explicitly communicated to the provider.
- **Simplicity**: No new AI orchestrator, no new Break-Glass overlay, and no duplicated schema structures are necessary.
